## Sprint Scope

### 1. Align Edge Functions — Payment Flow Bridge

Fix the `create-payment-preference` Edge Function to:
- First create a `payments` row (status=`pending`) linked to the booking hold
- Use the new `payments.id` as `external_reference` for the MP preference
- Return `{ payment_id, preference_id, init_point, expires_at }`
- This aligns with what `process-mp-webhook` expects

Fix the `process-mp-webhook` to:
- After payment approved, call `confirm_booking_from_payment` RPC (currently not called)
- Follow the architecture doc's payment lifecycle exactly

### 2. Booking → Checkout Flow

Update `NovaReservaForm.tsx`:
- After `createHold.mutateAsync()` succeeds, call `createPaymentPreference.mutateAsync(holdId)`
- Display payment options drawer/modal after hold creation
- Show `init_point` (MP checkout URL) as a payment link/button
- Add loading state during preference creation
- Handle errors (hold expired, MP error, etc.)

### 3. Payment Status Polling + Webhook Confirmation

Create `apps/web/src/hooks/usePaymentPolling.ts`:
- Poll `paymentService.getById()` every 5s while payment status is `pending`
- Auto-stop when status changes to `completed`, `failed`, or `refunded`
- Return current status, loading, error

Integrate polling into:
- `PaymentDetailDrawer.tsx` — show live status updates
- Booking detail view — show payment confirmation status

### 4. Dashboard KPIs — Live Data

Migrate `DashboardKPIs.tsx` from mock to live:
- Reservas Hoje → `count bookings WHERE created_at = today AND tenant_id = X`
- Transfers Ativos → `count bookings WHERE status = 'confirmed' AND tenant_id = X`
- Motoristas Ativos → `count drivers WHERE status = 'active' AND tenant_id = X`
- Ocupacao Media → `avg(occupied_seats / capacity) FROM vehicle_slots WHERE date = today`
- Receita Confirmada → `sum(amount) FROM payments WHERE status = 'completed' AND tenant_id = X`
- Check-ins Pendentes → `count bookings WHERE status = 'confirmed' AND check_in IS NULL`

Create `apps/web/src/services/dashboard.ts` with all KPI queries.
Create `apps/web/src/hooks/useDashboardKPIs.ts` with React Query hooks.

### 5. Realtime Subscriptions

Add Realtime subscriptions using the existing `useRealtime` hook from `@connect/ui`:
- `DashboardKPIs.tsx` — subscribe to `INSERT/UPDATE on payments` and `INSERT/UPDATE on bookings` to auto-refresh KPIs
- `DashboardFinancialOverview.tsx` — subscribe to `INSERT/UPDATE on payments` for live revenue updates
- `PaymentsList.tsx` — subscribe to `UPDATE on payments` for live status changes
- `PaymentsSummaryStrip.tsx` — live KPI updates via payment changes

### 6. Extend PaymentStatus Type

Update `packages/core/src/types/database.ts`:
- Add `overdue`, `partial`, `cancelled`, `paid`, `processing` to `PaymentStatus`
- Add `PaymentMethod` type: `pix | credit_card | debit_card | bank_transfer | cash | payment_link`
- Add `PaymentWithDetails` type (already used in UI but may not exist in core)
- Ensure backward compatibility with existing RPC return types

### 7. PaymentNotifications / Alerts

Update `DashboardAlerts.tsx`:
- Replace mock alerts with real data from Supabase
- Show alerts for: overdue payments, failed webhooks, booking conflicts
- Use Realtime to show alerts as they happen
