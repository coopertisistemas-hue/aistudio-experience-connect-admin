## Tarefas

### 1. Integrar TenantProvider no App.tsx

**Arquivo:** `apps/web/src/App.tsx`

Adicionar `TenantProvider` envolvendo `<BrowserRouter>`. O TenantProvider deve receber um `resolveTenant` callback que busca o tenant do usuário logado:

```tsx
// Estrutura final:
<I18nextProvider i18n={i18n}>
  <AuthProvider>
    <TenantProvider resolveTenant={resolveUserTenant}>
      <BrowserRouter basename={__BASE_PATH__}>
        <AppRoutes />
      </BrowserRouter>
    </TenantProvider>
  </AuthProvider>
</I18nextProvider>
```

O `resolveUserTenant` deve:
- Aguardar o usuário estar disponível (via AuthContext)
- Consultar `user_tenants` via Supabase: `supabase.from('user_tenants').select('tenant_id, role').eq('user_id', user.id).single()`
- Retornar o `tenant_id` ou `null`

### 2. Implementar TenantProvider com resolução real

**Arquivo:** `packages/ui/src/providers/tenant-provider.tsx`

Substituir o stub atual por implementação real:
- Aceitar `supabase` client como prop
- Quando `user` muda, buscar `user_tenants` 
- Suportar `initialTenantId` para cenários offline
- Provider deve expor: `tenantId`, `organizationSlug`, `userRole`, `isLoading`

Atualizar `TenantContextValue` em `packages/ui/src/hooks/use-tenant.ts` para incluir `userRole: string | null`.

### 3. Adicionar RoleGuard component

**Arquivo:** `apps/web/src/components/feature/RoleGuard.tsx` (novo)

Criar componente que verifica a role do usuário:
```tsx
interface RoleGuardProps {
  children: React.ReactNode;
  allowedRoles: string[];
  fallback?: React.ReactNode; // opcional: o que mostrar se não tiver role
}
```

Se o usuário não tiver role permitida, redirecionar para `/` ou mostrar fallback.

### 4. Atualizar ProtectedRoute com role checking

**Arquivo:** `apps/web/src/components/feature/ProtectedRoute.tsx`

Adicionar verificação de role. A route `/admin/*` exige role `admin` ou `operator`.

### 5. Atualizar router config

**Arquivo:** `apps/web/src/router/config.tsx`

- Rotas públicas: `/`, `/login` — sem role guard
- Rotas admin: `/admin/*` — require role `admin` | `operator`
- Futuro: rotas de guest/hóspede — require role `guest`
