# Milestone v0.5.0 - Live Data Integration

## Objective
Transition the unified frontend from mocked data to live integration with the Supabase backend. Hardening the authentication and tenant isolation layers while activating the core transactional flows (Bookings & Payments).

---

## Phases & Deliverables

### 1. Auth + Tenant Hardening
- [ ] Migrate Auth Context to use `packages/core` Supabase client.
- [ ] Implement robust tenant resolution from URL/Subdomain.
- [ ] Enforce route guards based on tenant membership and roles.
- [ ] Stabilize Login/OTP flow with real Supabase Auth.

### 2. Supabase Client Unification
- [ ] Audit and remove redundant Supabase client instances in `apps/web`.
- [ ] Ensure all data fetching utilizes the unified client from `@connect/core`.
- [ ] Implement standardized error handling and loading states for data fetching.

### 3. Bookings Live Integration
- [ ] Connect Guest App booking flow to `create_booking_hold` Edge Function.
- [ ] Implement real-time slot availability updates using Supabase Realtime.
- [ ] Connect Admin Agenda view to live `vehicle_slots` and `bookings`.

### 4. Payments Live Integration
- [ ] Integrate Mercado Pago frontend SDK (Proceso de Pago).
- [ ] Connect checkout flow to `create_payment_preference` Edge Function.
- [ ] Implement payment status polling and webhook confirmation feedback in UI.

### 5. Realtime Operations
- [ ] Activate Realtime subscriptions for Admin Dashboard KPIs.
- [ ] Implement real-time notifications for operators on new bookings/payments.
- [ ] Synchronize Guest App booking status with live backend state.

### 6. Mercado Pago Integration Hardening
- [ ] End-to-end testing with Mercado Pago Sandbox.
- [ ] Handle payment edge cases (declined, pending, expired) in UI.
- [ ] Validate idempotency and reconciliation UI in Admin Panel.

### 7. Production Hardening
- [ ] Environment variable audit for Staging/Production.
- [ ] CORS configuration for Edge Functions and Supabase.
- [ ] Sentry integration for frontend error tracking.
- [ ] Final Playwright E2E suite for critical "Live" paths.

---

## Technical Constraints
- **Zero Redesign:** Maintain the UI foundation certified in v0.4.0.
- **Type Safety:** Ensure all Supabase responses are correctly typed using generated types.
- **Isolation:** Verify tenant isolation at the API level (RLS) is correctly handled by the frontend.

---

## Success Criteria
1. Guest can complete a booking flow with real inventory locking.
2. Payment confirmation triggers real booking state transition.
3. Admin Agenda updates in real-time as bookings are made.
4. No cross-tenant data leakage in the UI.
